# Library Project

Учебный pet-проект «Система управления библиотекой» — асинхронный backend на **FastAPI** и **SQLAlchemy 2.0** (async) с миграциями через **Alembic**.

Проект реализует базовую предметную область библиотеки: авторы, жанры, книги, читатели и выдачи книг (loans), а также REST API поверх этой логики.

## Стек технологий

- **Python 3.13**
- **FastAPI** — веб-фреймворк, REST API
- **SQLAlchemy 2.0** (async, `sqlite+aiosqlite`) — ORM и работа с базой данных
- **Alembic** — миграции схемы БД
- **Pydantic** — валидация входных данных API
- **uvicorn** — ASGI-сервер

## Структура проекта

```
library_project/
├── main.py                 # точка входа FastAPI-приложения, сборка роутеров
├── library.db               # файл базы данных SQLite
├── alembic.ini               # конфигурация Alembic
├── alembic/                  # миграции базы данных
└── app/
    ├── models.py              # ORM-модели (Author, Genre, Book, Reader, Loan)
    ├── database.py            # асинхронный engine и сессия SQLAlchemy
    ├── crud.py                # бизнес-логика и CRUD-операции с БД
    └── routers/
        ├── books.py             # эндпоинты для книг
        ├── readers.py            # эндпоинты для читателей
        └── loans.py              # эндпоинты для выдачи/возврата книг
```

## Модель данных

- **Author** — автор книги (`id`, `name`)
- **Genre** — жанр книги (`id`, `name`)
- **Book** — книга (`id`, `title`, `year`); связана с `Author` и `Genre` через отношение many-to-many (таблицы `book_author`, `book_genre`)
- **Reader** — читатель библиотеки (`id`, `name`)
- **Loan** — факт выдачи книги читателю (`id`, `reader_id`, `book_id`, `borrowed_at`, `returned_at`); `returned_at = NULL` означает, что книга ещё не возвращена (активная выдача)

Бизнес-правило: книгу нельзя выдать повторно, пока не оформлен возврат предыдущей выдачи (проверяется в `lend_book`).

## Установка и запуск

1. Создать и активировать виртуальное окружение:

```bash
python -m venv .venv
.venv\Scripts\activate       # Windows
```

2. Установить зависимости:

```bash
pip install fastapi uvicorn sqlalchemy aiosqlite alembic pydantic
```

3. Применить миграции (создать/обновить схему базы данных):

```bash
alembic upgrade head
```

4. Запустить сервер:

```bash
uvicorn main:app --reload
```

5. Открыть интерактивную документацию API (Swagger UI):

```
http://127.0.0.1:8000/docs
```

## API — эндпоинты

### Книги (`/books`)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/books` | Создать книгу (`title`, `author_ids`, `genre_ids`, `year`) |
| GET | `/books/{book_id}` | Получить книгу по id (авторы и жанры включены в ответ) |

### Читатели (`/readers`)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/readers` | Создать читателя (`name`) |
| GET | `/readers/{reader_id}` | Получить читателя по id |

### Выдачи книг (`/loans`)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/loans` | Выдать книгу читателю (`reader_id`, `book_id`). Вернёт `409 Conflict`, если книга уже выдана и не возвращена |
| POST | `/loans/{book_id}/return` | Оформить возврат книги. Вернёт `400 Bad Request`, если активной выдачи для этой книги не найдено |
| GET | `/loans/active` | Список всех активных (не возвращённых) выдач с именем читателя и названием книги |

## Архитектура

- **`app/database.py`** — создаёт асинхронный движок SQLAlchemy и функцию-зависимость `get_session`, которая через `yield` открывает сессию БД перед обработкой запроса и закрывает её после (в том числе при ошибке).
- **`app/crud.py`** — слой доступа к данным: функции создания записей и бизнес-логика (выдача/возврат книги), не зависящие от FastAPI.
- **`app/routers/`** — каждый файл содержит `APIRouter` для своей группы сущностей (книги, читатели, выдачи) со своими Pydantic-схемами запросов; роутеры подключаются к приложению в `main.py` через `app.include_router(...)`.
- **`main.py`** — минимальный файл: создаёт `FastAPI()` и регистрирует все роутеры.

Такое разделение позволяет расширять проект новыми сущностями и эндпоинтами, не раздувая один файл.
